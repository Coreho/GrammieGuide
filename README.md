# GrammieGuide

_Last updated: 2026-10-27_

A clean rewrite of `grandmas-launcher` - a dementia-friendly kiosk launcher for an elderly user, with a caregiver admin panel. Electron + React + TypeScript.

This is a **separate repo from `grandmas-launcher`**, which keeps running untouched on the real device as the safety net while this rewrite is built. Nothing here is merged from or into that repo - old code is referenced by path for patterns only.

Full rewrite plan (context, decisions, architecture, milestones): see the plan document from the planning session (`i-kinda-wanna-overhaul-moonlit-prism.md`).

## Home tiles

In **admin → Tiles**, add websites, installed apps (full Windows paths), or a built-in (Weather, News, Photos, Music, Games or Knitting). Pick an icon, a color, normal or wide size, and a position on Home. Changes reach Home immediately.

Home has a fixed layout chosen in **admin → Tiles → Home layout**: **Simple four** (four large tiles in two rows, labels up to 28 characters) or **More choices** (eight smaller tiles in two rows, labels up to 18 characters). Where a tile sits is part of how she finds it, so every tile keeps its position: adding, editing or removing another tile never moves it, and removing a tile leaves a gap rather than sliding the others over. A wide tile takes two neighbouring spaces in the same row. Home always fits on one screen at every text size, with no scrolling. Labels never break in the middle of a word; if a long word doesn't fit its tile at a large text size (say "photographs" in More choices at the largest size), only that label's text shrinks, just enough to fit. When the layout is full, admin says so; a tile that doesn't fit is kept and listed as "Not shown on Home" instead of being deleted, and admin flags labels longer than the layout allows. The footer keeps a fixed space for **Ask {name} to call**, and the date row has its now-playing chip, so enabling these controls never reshuffles her tiles.

The built-in Photos, Music, Weather, News and Games tiles show a clay picture of a photo stack, a radio, a sun and cloud, a newspaper, and game pieces. The pictures are bundled with the app, so they work offline; the weather picture is only there so she recognizes the tile, not a forecast. In **admin → Tiles → Card artwork** any tile can use one of these pictures, or the Games or Websites artwork; the picture never changes where the tile goes. A photo chosen for the tile takes priority, and a custom icon replaces the artwork. In **More choices**, normal-width tiles have room only for their label, so the artwork appears on wide tiles. If a picture can't load, the tile shows its usual icon.

**Clay cards** (admin → Display) is the theme that matches the approved card design: a cream background, deeper tile colors and bigger, bolder labels. It is opt-in, so updating never changes the theme she already has.

**Background** (admin → Display) puts a calm color behind Home and her full-screen views (News, Photos, Music, Games and the web page bar) in place of the theme's own: Cream, Sage green, Soft blue, Blush pink or Lavender with the light themes, and Midnight blue, Forest green, Plum, Charcoal or Deep teal with the dark ones. Cards, tiles and text keep the theme's colors, so only backgrounds her text stays easy to read on are offered. Switching to a theme of the other kind shows that theme's own background but keeps the choice, which comes back with a matching theme. **Theme default** goes back to the theme's background.

Each tile also keeps its own color when tiles are added or removed, because the color is part of how she recognizes it; new tiles start with a color Home isn't using yet. Colors look different in the two "Tiles" themes and in Clay cards; the four other clay themes share one tile color. Leaving a web page, by the Home button or the idle timeout, closes it completely, so a video or radio stream stops instead of playing on out of sight.

If a web page won't load, she never sees Chromium's technical error page. A calm screen says "This page won't open right now." with big **Try again** and **Home** buttons. When the internet is down it says so, and the page opens by itself once the connection is back. A link the kiosk won't follow gets the same screen with **Back to the page**. The Home button stays in its usual place at the top, and admin → Activity shows which site failed and why.

Text size is set only by the caregiver, in **admin → Display**, and Home follows it immediately. Home no longer has its own text-size buttons (the A-/A+ in the bottom-left corner), so a stray tap can't change it.

A web page closes by itself after the caregiver's idle time (admin → Confusion). Each tap, key press or scroll inside the page restarts that timer. Reading without touching anything doesn't, so a page she only reads still closes once the time is up. Before 2026-09-30 input inside the page didn't count at all, because the page's small activity-reporting script never loaded. Events a page fakes with its own scripts are ignored. Home, admin and web pages all run in Chromium's sandbox, which limits what a misbehaving page could do to the computer.

Web pages run in their own browser session, separate from Home and admin, so nothing a site asks for reaches the rest of the app. Every permission is denied (camera, microphone, location, notifications, clipboard), downloads are cancelled and logged as `browser-download-blocked`, and a page cannot put an alert, a prompt or a "leave this page?" question on her screen. Ads and trackers are blocked in that session too. The filter lists are saved on the computer, so blocking works with no internet; once a day (and a few minutes after start when the saved copy is over a day old) they are rebuilt from the current lists and saved again. A failed refresh keeps the old lists. If blocking ever can't start at all, browsing carries on unfiltered and admin → Activity records `adblocker-unavailable`. One consequence worth knowing: the first time after this change, she is signed out of websites, because the session moved.

Built-in tiles each have their own view. **News** is wide by default. New News tiles open three upright website-preview cards: **Yahoo News**, **BBC News**, and **NBC News**, left to right. Each opens its website in the protected kiosk browser; Back from the site's first page returns to the choices, and Home closes the page. Previews load in muted, sandboxed pages one at a time, time out after ten seconds, and are cached for fifteen minutes. A missing preview leaves a usable named card. In **admin → Tiles → News layout**, caregivers can edit the website choices or select **Stories from a feed**. Existing feed tiles retain their story list and optional website fallback. The top headline is deliberately not shown on the Home tile itself. **Games** opens a calm Games hub with four untimed offline games (**Matching Pairs**, **Picture Puzzle**, **Tic-Tac-Toe**, and **Melody Chimes**) plus any local installed Windows games added in **admin → Games**.

**Knitting (add a Knitting built-in tile, then set it up in admin → Knitting).** Tapping the tile opens a shelf of large cards. **My project** shows what she is knitting and the row she is on, with her project photo or a yarn picture. Inside, the row number is large, with a big **Add a row** button and a smaller **Take one away**. A second tap on the same button within 1.5 seconds is treated as a double tap and ignored, so the count never jumps by two; a correction the other way always counts. With idle dimming on, a tap on the counter brightens the screen and still counts, since she taps it minutes apart. Home has no reset: only the caregiver can reset the count, save details as a new project (row 0) or remove the project, and admin shows her current row live. Her project and count are kept in their own file in the app's data folder, not in settings, so they survive restarts and Home recovery, and they are not part of settings backups. Logs record only that a row was counted or the project changed, never what she is making or who it is for. Until a project, pattern or finished piece is set up, the shelf shows a calm line instead of cards.

**Knitting patterns (admin → Knitting → Patterns).** Name the pattern, then choose its pages: clear photos or saved pictures of each page, all at once (up to 60, shown in file-name order, so name them page1, page2 and so on). Each page is decoded and saved as a JPEG up to 2400 pixels on its longer side, more than photos get, so pattern text stays sharp; the original files are never used. On Home the **Patterns** card opens the pattern straight away (or a list when there are several). She sees one page at a time on a paper-colored page that fills the screen, with **Page 2 of 5** between large **Back** and **Next** buttons, and the pattern reopens on her last page, even after a restart. Choose a pattern for her project and the project view gets a **Pattern** button. Removing a pattern removes its pages and its link to the project. Patterns are not part of settings backups.

**Her finished knitting (admin → Knitting → My knitting).** Type what the piece is and, if it went to someone, who it was for, then choose one photo of it. The photo is decoded and saved as a JPEG up to 1600 pixels on its longer side, like her family photos; the original file is never used. New pieces go first; **Move earlier** and **Move later** change the order, and **Remove** deletes the piece and its photo (up to 100 pieces). On Home the **My knitting** card opens her gallery: one piece at a time, shown whole, with its name and **For Ella** underneath, and **1 of 12** between large **Back** and **Next** buttons. A piece whose photo is lost keeps its caption with a calm line in place of the picture. Logs record only that a piece was added, moved or removed, never what it is or who it was for. Pieces are not part of settings backups.

In **admin → Reliability → Settings backup and restore**, **Save backup** writes all settings and tiles to a JSON file you choose. **Restore backup** replaces the current settings and tiles from that file, upgrades older settings through the config migrations, and updates Home immediately. Save a backup before restoring if you want to keep the current setup. An invalid or unreadable backup is rejected in plain words without changing settings.

Backups exclude ChatGPT tokens and caregiver PIN hash/salt; restore keeps the destination device's existing secrets. Photo and music files and their separate library indexes are not included. Import media separately on another device. The Photos viewer shows a calm empty state when this device has no photos; missing songs make the saved playlist unavailable until music is imported and assigned again. Contact channels are not in the current config schema, so no contact tokens are exported; backup support must be extended alongside their future schema.

**Photos (admin → Photos).** The caregiver adds family photos through the Windows file picker: JPG, PNG and WebP, and HEIC when this computer can decode it. Each photo is shrunk to at most 1600 pixels on its longer side, saved as a JPEG with a small thumbnail, and the original file is left where it was. A photo that can't be read is counted as failed and the rest of the batch carries on, with a running count while it works. Each photo gets an optional caption, a **Show to her** switch (on for new imports) and an order number. The photo viewer receives only the photos marked to show.

**Photo viewer (add a Photos built-in tile in admin → Tiles).** One large picture and its saved caption appear at a time, with large Back, Next and Home buttons. Pictures stay still until she chooses another. The caregiver can turn on **Gentle slideshow** in admin → Photos: it waits 30 seconds after each picture loads, restarts that wait after manual paging, and offers her Pause/Play. Leaving the viewer stops it. It works offline, never asks questions or tests her memory, and records only that the viewer was opened, never photo content or captions. Empty libraries and unavailable pictures get calm wording and a way Home. Unusually long captions scroll within their own area so the picture and navigation remain on screen.

**Recorded photo stories (admin → Photos).** Record a familiar voice with the microphone or attach an audio file, preview it, re-record it or delete the story while keeping the photo. Audio is limited to five minutes and 20 MB, validated before saving, and stored as its own managed copy; the original audio file is kept. Microphone access is restricted to the unlocked caregiver panel. Leaving Photos or locking admin ends recording and preview playback. In the viewer, **Listen to the story** plays the narration offline and **Stop story** ends it. Autoplay is off unless the caregiver enables it for that photo. Narration pauses music, stops on paging or Home, and holds the slideshow on its current picture until it ends. Recorded audio is not included in settings backups; import it separately on another device.

Config migrations 003 (tile sizes), 004 (saved Buddy messages), 005 (tile colors, seeded so upgrading doesn't repaint Home), 006 (Buddy tap and motion choices), 007 (the chat switch, on for existing setups), 008 (fixed Home layouts, with no tile dropped), 009 (photo slideshow off by default), 010 (optional tile photos), 011 (music playlists and listening settings), 012 (optional card artwork and the Clay cards theme), 013 (idle dimming, off for existing setups), 014 (the caregiver's approved sites, empty for existing setups) and 015 (the Games hub settings and installed games list) preserve existing settings.

Every config save is validated against the schema before anything is written, and the parsed result is what reaches disk. One unvalidated value used to cost everything: the next boot would fail validation, fall back to defaults, and wipe her tiles, the API key and the PIN hash - after which anyone at the kiosk could set a new PIN. If the config file itself is unreadable (truncated, zero-length or hand-edited), the app now copies it byte-for-byte to `config.corrupt-<timestamp>.json`, records a `config-reset` event in the reliability log, and starts from defaults instead of crash-looping. The reset log never contains config values or a parser message, because both can quote the file's contents. **After such a reset, set the PIN again straight away**, since the kiosk is running without one.

Local media infrastructure is ready: `grammie-media://` streams images and seekable audio from `userData/media/music/` and `userData/media/photos/` to Home and admin, with strict filename validation and no renderer filesystem API. The caregiver-side library store is in place too. Each library keeps its own `index.json` beside its files, separate from config. Importing copies files in under generated names, and the original path is never kept. A damaged index is backed up and the library starts empty instead of stopping the kiosk. Photos have their admin screen and Home viewer (above); photo changes go only through admin, so every photo is decoded and resized. Music has its caregiver library, playlists and Home player.

Photos are imported through admin → Photos (JPG, PNG, WebP and, where Windows can decode it, HEIC); every photo is actually decoded, and one that isn't a readable image just counts as failed. Music imports accept MP3, WAV, OGG/OGA, OPUS, M4A, AAC, FLAC and WEBM files. Extensions are checked without regard to case, and the picker offers only music types. If any selected music file has an unsupported extension, the whole batch is rejected before copying anything, with a plain message listing the accepted kinds. These music checks do not verify a file's contents or encoding.

On each library instance's first load, its operation queue removes leftover `.import.tmp` and `.index.tmp` files and, only when the index parses successfully, unlisted files with generated media names. Listed files, corrupt-index backups and unrelated files are preserved. After a corrupt index is backed up, only temporary files are removed; all media files are preserved, because a backup cannot tell us which files were in use. Cleanup is lazy, so it adds no kiosk startup work, and it is skipped if the index is unreadable, a corrupt index cannot be backed up, or the library has no index yet. Busy files are left for the next instance's load; cleanup failures do not stop library use.

## Buddy

Buddy is the cat in sunglasses at the bottom right of Home.

- **On his own** he follows the caregiver’s motion choice: **Stays put** keeps his usual gestures without wandering; **Walks now and then** keeps today’s fidgets and strolls across the full footer (never over the tiles); **Reduced motion** keeps him in place with no unprompted fidgets and fewer, gentler gestures. From 9 PM to 6 AM he stays put and keeps quiet. With chattiness turned on he occasionally says something in a speech bubble (never out loud).
- **Noticing her:** closing Weather, News, Music or another built-in view gets a small wave (a heart after her pictures), at most every 20 seconds and never during chat, a caregiver command or a walk. His first quiet moment each morning is a big stretch (not in reduced motion). While her music plays his fidgets sway and dance along, except at night, when he may doze. When she taps somewhere on Home he glances toward it; reduced motion makes the glance smaller and slower.
- **Tap him** to open chat right away if the caregiver chooses that setting. Otherwise, a tap gives a short friendly bubble and a matching happy gesture, without repeating the previous tap's line or animation. In reduced motion the tap gestures are small waves and hearts. He reads it aloud when the caregiver's read-aloud setting is on. Taps work at night, and repeated taps restart the reaction without stacking speech. His bubble also offers a big **💬 Let's chat** button for eight seconds after each tap, even if the gesture ends sooner; it then fades away. Opening chat, the caregiver menu or leaving Home dismisses it. During chat, tapping him stays a pet.
- **Caregiver menu:** press **Ctrl+Shift+B** on Home for **Let's chat**, **Dance**, **Wave**, **Say something nice**, or **Take a walk**. The small translucent card opens above where Buddy is standing and stays on screen near the edges. Press the shortcut again, Esc, or click outside to close it. Arrow keys and Tab move between commands; Enter chooses one. It stays closed in the browser and over chat, weather or confusion overlays. **Take a walk** sends him at least a third of the floor away, even at night or in reduced motion, then he rests.
- **Chat:** tap Buddy once if set to open chat directly, or choose **💬 Let's chat** after his reaction. The caregiver menu also offers **Let's chat**. He joins the panel, waves, listens while she talks or types, scratches his head while thinking, and gestures while answering. Each line opens with a gesture that fits its words (a wave for hello, a heart for something warm, a bow for thanks, a cheer for good news; never a cheer for sad news).
- **Ask him for a gesture:** typing or saying a whole request such as "dance", "Buddy, wave to me", "take a bow" or "show me a trick" makes him do it in the chat with a short fixed line, even without ChatGPT. With ChatGPT connected, other wording can ask for the same gestures through a fixed tool. Sentences that only mention a gesture ("I used to dance") stay conversation. Reduced motion swaps big gestures for a wave or a heart. The **Talk** button lets her speak instead of type; it only appears when a microphone is found. Reduced motion keeps him where he is, uses a listening pose while thinking, and plays just one talking gesture per reply. Closing the chat gets a goodbye.
- **What he says:** he never argues with something confused, never agrees that it is true, and never makes up facts about her family, plans or visits. When she says her mother is coming or she has to get to work, he asks about the person or the job instead ("Your mother. What is she like?"). Asked something he can't know, he suggests she ask her family. He runs on Claude Sonnet 5.5 by default, because live checks found the cheaper Haiku 4.5 still going along with confused statements.
- **Caregiver settings** (admin, Buddy tab): whether chat is allowed at all, ChatGPT account and verified model, chattiness, what her tap does, how much he moves, whether replies are read aloud, whether to use the online voice and which one (with **Try this voice**), and the voice on this computer (with **Try this computer's voice**; the first try takes a few seconds to load). Tap, motion and chat choices apply on Home immediately, without a restart. Turning chat off closes an open chat and removes every way into it, while Buddy stays on Home with his friendly tap reactions. Choose by watching what she enjoys and what distracts her; more animation is not automatically better. Existing settings migrate: strolling on becomes **Walks now and then**, and off becomes **Stays put**.
- **Ask Buddy to do something:** chat has large **Play my music**, **Show my pictures** and **Go Home** buttons. The same direct requests work when typed or spoken, even offline without an AI key. Music uses the first saved playlist with an available song; pictures use the approved photo library, even without a Photos tile. General wording can ask the chat provider to propose only these same three actions. Main validates the proposal, and any premature success text is discarded. Music is confirmed only after local playback starts; unavailable media gets a kind setup message. The model cannot open arbitrary pages, files or other actions.
- **Command Buddy** (admin, Buddy tab): play any of his 29 animation clips, ask him to take a walk, send a short message with a gesture and optional read-aloud, and save/remove quick messages. Commands work in every motion mode on Home, including at night, and are ignored while she is chatting. Each gesture plays once, with a 20-second recovery timeout. Read-aloud uses the same voices as his chat. Message content is never written to the activity log.
- **His voice:** the voice on this computer (the online Edge voice comes first only if the caregiver turns it on, and only when it is working), and the Windows voice only if neither can speak. The voice on this computer runs in its own background process, so a problem there can't affect Home; it loads a few seconds after start-up when the online voice is off, and otherwise the first time it is needed (that one line uses the Windows voice). Long replies are spoken in pieces, so he starts talking once the first sentence is ready. Admin → Checks reports which voice actually played.

Buddy fills his floor and stays on screen whatever the screen size. The Stage is a
fixed 1440x900 design scaled to fit, so his canvas measures its own layout size
rather than the scaled box - otherwise the scale would be applied twice and he would
roam only part of his floor, float, and drift out of reach at the ends.

### Rebuilding his model

The model (`src/renderer/launcher/src/buddy/assets/buddy.glb`) is generated. The inputs are Meshy downloads in `CatModel/meshy/` (gitignored, ~390 MB, not in the repo): the auto-rigged cat plus library animations bought with `meshy animate create`. `sh scripts/blender/buildBuddy.sh` (Blender 5.2, ~70s) fixes the rig for his shape and bakes every clip into the GLB. ## Installing on the kiosk

Build the installer with `npm run package` (output in `dist/`), then follow [docs/kiosk-install.md](docs/kiosk-install.md). In short, from an administrator PowerShell on the kiosk:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\kiosk\switch-to-grammieguide.ps1 -Installer "GrammieGuide Setup 0.1.0.exe"
```

Then set a PIN, run **Tiles → Import settings from Grandma's Launcher**, set up her tiles fresh, and add the Buddy API key. `scripts\kiosk\rollback-to-grandmas-launcher.ps1` goes back to the old launcher, which is never uninstalled.

The switch keeps the old launcher's start-at-login on until GrammieGuide has set up its own. If the installer is cancelled or fails, the script stops, turns the old watchdog back on and reopens the old launcher, so she never signs in to neither. It also switches off any leftover startup entry from early builds of the old launcher (as Task Manager does); rollback turns back on only the entries the switch turned off.

## Settings safety

Every settings change is checked against the config schema before it is saved, and what reaches disk is the checked result - so a stray unknown key is dropped rather than accumulating in the file. A change that would not pass is refused outright and nothing is written: the form keeps its last good values and no change is pushed to her Home screen.

If the settings file itself cannot be read - truncated by a power cut, emptied, or hand-edited - GrammieGuide copies it byte-for-byte to `config.corrupt-<timestamp>.json` next to the original, notes it under **admin -> Reliability**, and starts from default settings. It does this instead of crashing, because a crash loop on a kiosk is the one failure nobody is there to notice.

Two things to know after such a reset:

- **Set the PIN again straight away.** The reset cleared it, so until you do, anyone at the keyboard can open the admin panel and set one.
- The copy beside the original is the only record of what was there. Nothing is logged from its contents - the note in Reliability deliberately names the file rather than quoting it, so the API key or PIN hash cannot end up in a log.
