# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

GrammieGuide is a dementia-friendly Windows kiosk launcher for an elderly user, plus a PIN-gated caregiver admin panel. Built with Electron, React 19, TypeScript and electron-vite. It is a clean rewrite of the older `grandmas-launcher` repo, which keeps running on the real device as the safety net. Code from that repo is referenced for patterns only; never merge between the two. Many comments explain what an old-app pattern was replaced with and why, so keep that context when editing.

Work is organized into milestones (M1 reliability spine, M2 Home + admin, M3 3D Buddy, …) from an external plan doc (`i-kinda-wanna-overhaul-moonlit-prism.md`, not in this repo). The README's Status section tracks which milestones are done.

Planned work lives in Backlog.md (`backlog task list --plain`; the CLI is not an npm dependency, so install it once with `npm i -g backlog.md`), grouped into milestones such as Predictable Home, Contact family and Protected browsing. The older V2 feature specs in `docs/specs/` (read `00-overview.md` first) are background for some tasks. They predate M4 and the News tile, and their scam scoring, photo games and presence features are on hold as drafts. Where a task and its spec disagree, the task wins.

`@ghostery/adblocker-electron` blocks ads and trackers in the embedded browser's session (`services/browser/adBlocker.ts`). Startup loads the engine from its on-disk cache, so it never needs the network after the first run; a refresh builds a whole new engine from the lists, swaps it in and saves it over the cache (adding lines to the running engine kept rules the lists had dropped). (`msedge-tts` and `xstate` are used by Buddy's voice and behavior machine.)

## Commands

- `npm run dev`: run the app with HMR. Kiosk lockdown is **off** in dev (`KIOSK_ENABLED = !is.dev` in `windowManager.ts`).
- `npm run build`: typecheck, then `electron-vite build` into `out/`
- `npm run typecheck`: runs both `tsconfig.node.json` (main/preload/shared) and `tsconfig.web.json` (renderers)
- `npm run lint`
- `npm test`: Vitest unit tests (`tests/unit/**/*.test.ts`, node environment)
- Single test file: `npx vitest run tests/unit/urlPolicy.test.ts`, or filter by test name with `-t "<name>"`
- `npm run test:e2e`: Playwright against the **built** app (`electron .` launches `out/main/index.js`). Run `npm run build` first. It uses a fresh temp `--user-data-dir` and sets `GRAMMIEGUIDE_E2E=1`, which exposes `globalThis.__e2e__.createAdminWindow` because Playwright can't send the Ctrl+Shift+A shortcut to a kiosk window. The same switch makes every app window invisible, click-through, unfocused and absent from the taskbar (`QUIET_E2E_WINDOWS` in `windowManager.ts`), so a run never interrupts whoever is using the computer; tests must not depend on real OS focus or mouse, which Playwright doesn't use anyway. Moving windows off-screen instead broke the kiosk-size tests (no monitor to take scaling from).
- `sh scripts/blender/buildBuddy.sh`: rebuilds Buddy's model (`src/renderer/launcher/src/buddy/assets/buddy.glb`) from the Meshy downloads in the gitignored `CatModel/meshy/`. Needs Blender 5.2 (override the path with `BLENDER=`); takes about 70s. See "Buddy's model" below.
- `npx tsx scripts/debugReliability.ts`: manual real-hardware check of the Wi-Fi, volume and scheduled-task code. It registers both tasks, runs the watchdog once against a throwaway folder to prove it executes, then removes them. Safe to re-run on a dev machine; not on a kiosk where GrammieGuide is installed, since it replaces and then removes the real tasks.
- `npm run package`: Windows NSIS installer into `dist/` (config is the `build` block in `package.json`; icon and uninstall hook in `build/`). Installing it for real is documented in `docs/kiosk-install.md`, with the switch/rollback scripts in `scripts/kiosk/`.

Shortcuts: `Ctrl+Shift+Q` always quits. `Ctrl+Shift+A` opens the admin window, and so does `Ctrl+Shift+Esc` in kiosk mode. `Ctrl+Shift+B` toggles the caregiver Buddy menu on Home (outside chat, weather and confusion overlays).

## Architecture

Three processes, each with its own electron-vite entry. The `@shared` alias resolves to `src/shared` in the main process, the preloads, the renderers and Vitest.

- **Main** (`src/main`): `index.ts` is a deliberately thin bootstrap. It takes Electron's single-instance lock first: a second launch exits before touching anything and focuses the running Home (the watchdog kills the old process before relaunching, so this never blocks recovery). It loads config, registers IPC, creates the launcher window, starts the embedded browser and inactivity watch, and starts the watchdog heartbeat. Put logic in `services/`, not in `index.ts`.
- **Preloads** (`src/preload`): `launcher.ts` and `admin.ts` expose typed APIs through `contextBridge` (`window.launcher`, admin equivalent). `browserView.ts` runs inside embedded web pages and reports user activity for the inactivity timeout. Both windows and the web view run with `sandbox: true`, so all three preloads are built as CommonJS (`.cjs`, set in `electron.vite.config.ts`): a sandboxed preload runs as a plain script and fails on an ES module `import`. At runtime a preload may load only `electron`'s renderer APIs (plus `events`, `timers`, `url`), so shared code has to stay `import type`. Until TASK-31 the web view's preload was an ES module and silently never loaded; `tests/e2e/sandbox.spec.ts` guards this.
- **Renderers** (`src/renderer/launcher`, `src/renderer/admin`): two separate React apps. The launcher is the kiosk Home screen, which includes tiles, weather, help and confusion overlays, and the Three.js Buddy cat in `buddy/`. The admin app is a tabbed caregiver panel behind `PinGate`, using a zustand store.

### IPC contract

`src/shared/ipcContract.ts` is the single source of truth for every channel. `IpcApi` holds invoke channels with request and response types; `IpcEvents` holds main-to-renderer push events. To add a channel:

1. Add it to `IpcApi` or `IpcEvents`.
2. Add the handler in the matching `src/main/ipc/<domain>Ipc.ts`. Each domain is registered from `ipc/index.ts`.
3. Expose it in the relevant preload.

Handlers that only a caregiver may use must call `requireAdminUnlocked()` first. This is enforced in the main process, not just by the UI gate. The unlock flag lives in memory in `services/auth/adminAuth.ts`, so it resets when the app restarts. The PIN is 4–8 digits, hashed with scrypt, and locks out for 30s after 5 failed tries.

### Config

- **Settings backup/restore:** `services/config/backup.ts` builds a versioned JSON envelope from schema-validated public config. `backup:save/restore` use native dialogs and `requireAdminUnlocked()` (rechecked after dialogs/reads). Restore calls `runMigrations` but rejects its failure result and empty/incomplete inputs, never applying boot fallback defaults. `mergeAdminPatch` preserves the latest device secrets; successful restore pushes `config:changed` to Home and refreshes admin's config store. Media files and separate library indexes are excluded. Contacts/tokens are not yet schema fields; adding contact channels must extend backup secret handling and tests. Restored Photos tiles use the registered photo viewer and its calm empty state; Music uses the registered player; playlists with missing media dim calmly.

- **Schema:** `src/shared/configSchema.ts` defines a zod schema, versioned by `CURRENT_SCHEMA_VERSION`. It is persisted through electron-store in `src/main/config/store.ts`.
- **Secrets:** `toPublicConfig()` strips PIN/contact secrets and obsolete Buddy credential fields before anything reaches a renderer. `setConfig` merges only one level deep, so `config:set` runs patches through `mergeAdminPatch()`, which always carries the current secrets forward. The PIN changes through `admin:setPin`; ChatGPT tokens live outside config in encrypted main-process storage.
- **Validation:** `config:set` goes through the pure `applyConfigPatch()` in `config/applyConfigPatch.ts` (one-level merge, then `configSchema.safeParse`) and saves the _parsed_ result, so unknown keys are dropped and defaults filled on the way to disk. An invalid patch throws `ConfigValidationError` before the cache or the file changes; `configIpc.ts` logs `config-updated` and pushes `config:changed` only after that succeeds, so a rejected save leaves no trace. Issues name field paths only, never values, because the message can reach the activity log. `store.ts` builds its `Store` lazily inside `loadConfig` - `electron-store` reads the file in its constructor and rethrows a `SyntaxError`, and `store.ts` is imported before `app.whenReady`, which used to crash-loop the kiosk on a truncated file. On `SyntaxError` the raw bytes are copied to `config.corrupt-<ts>.json` _before_ reopening with `clearInvalidConfig`; any other read failure (EPERM/EBUSY) is rethrown. Each reset records one `config-reset` reliability event naming the backup file; its reason is rebuilt from a fixed vocabulary because a JSON `SyntaxError` quotes the offending source and a migration's `TypeError` quotes its values.
- **Old launcher import:** `config/importOldLauncher.ts` maps grandmas-launcher's `%APPDATA%\grandmas-launcher\config.json` (read-only) to weather, display and confusion settings. Tiles are deliberately not imported (Home's tiles are set up fresh), behind `admin:previewOldLauncherImport` / `admin:applyOldLauncherImport`. It never carries secrets.
- **Schema changes:** bump `CURRENT_SCHEMA_VERSION`, then add a numbered pure migration file under `src/main/config/migrations/` (named `NNN-description.ts`) and list it in `migrations/index.ts`. The schema is at version 14: 003 adds tile sizes, 004 adds Buddy quick messages, and 005 gives each tile a saved `colorIndex`, seeded from its old position so upgrading doesn't repaint Home. 006 replaces `buddy.roaming` with `buddy.motion` (true → `roam`, false → `still`, missing → `roam`) and adds `buddy.tapAction` (default `reaction`). 007 adds `buddy.chatEnabled` (default true, so existing setups keep chat). 008 adds `display.homeLayout` and a nullable `slot` on each tile (see Tile positions below). 009 adds `photos.slideshowEnabled`, off by default. 010 adds optional tile photo IDs without changing existing icons or positions. 011 adds music playlists, a 90-minute auto-stop and now-playing chip preferences. 012 adds an optional tile `artwork` field and the opt-in `clayCards` theme; it only bumps the version, so saved tiles and themes don't change. 013 adds `display.idleDim` (enabled, afterMinutes 2-60, level 0.1-0.5), off for every existing install. 014 adds `approvedSites`, the caregiver's extra hostnames; existing installs get an empty list. The schema is lenient here on purpose: entries the site rule no longer accepts are dropped and the list is cut to 100, because one failing entry would otherwise fail the whole config at boot and reset her Home. Tile sites are derived at runtime, never copied into config. Existing values win over defaults. `runner.ts` applies the migrations in order and validates the final result against the current schema. If validation fails, it backs up the corrupt config and falls back to defaults so the kiosk still boots.

### Reliability (Windows-specific)

- **PowerShell:** every PowerShell call goes through `services/reliability/shellExec.ts` `runPowerShell()`. It uses `execFile` with a UTF-16LE base64 `-EncodedCommand`, never string-interpolates into a command line, and takes an injectable `execFileImpl` for tests.
- **Logging:** results are recorded with `logReliabilityEvent`.
- **Startup wiring:** `services/reliability/kioskServices.ts` (`startKioskServices()`, called from `index.ts`) turns everything on: volume ceiling every 30s (quiet unless it changes something), the Wi-Fi watch every 10s (`wifiWatch.ts`: restart the adapter after 60s offline, then a 5-minute cooldown), and, in the installed app only (`app.isPackaged` and not `GRAMMIEGUIDE_E2E`), registration of the scheduled tasks. Use `resourcesDir()` for anything under `resources/`: in the installed app it's `process.resourcesPath` (electron-builder `extraResources`), not inside the asar.
- **Scheduled tasks:** all registration goes through `scheduledTasks.ts`. `GrammieGuide` starts the app at her logon with no execution time limit (Task Scheduler's 72h default would kill the kiosk). `GrammieGuideWatchdog` runs `watchdog.ps1` every minute with `-ExecutionPolicy Bypass` (the default policy blocks `-File`). Both try the highest run level and fall back to limited. They're re-registered on every start, but a task someone disabled (the rollback script does) is left disabled; only the admin "Re-register" button forces it back on.
- **Watchdog:** the app writes a heartbeat file every 15s; the watchdog relaunches the app if it's over 90s stale. Ctrl+Shift+Q writes `quit-flag.txt` so a deliberate quit stays quit; the next start clears it. Keep `resources/watchdog/watchdog.ps1` ASCII-only and saved as UTF-8 with BOM (the same goes for `scripts/kiosk/*.ps1`, which must run on Windows PowerShell 5.1).
- **Home recovery:** the heartbeat comes from main, so it can't tell a crashed or frozen Home. `windowManager.ts` reloads the launcher itself: at once on `render-process-gone`, and after 10s of `unresponsive` (via `forcefullyCrashRenderer()` + `reload()`). It closes the embedded browser first, because a reloaded Home thinks no page is open. The decisions are pure (`services/reliability/homeRecovery.ts`). The 4th recovery within 5 minutes gives up: `app.exit(1)` without the quit flag, so the watchdog relaunches after its stale-heartbeat delay; never `app.relaunch()`, which would make a crash loop immediate. Before exit, a timestamped give-up record is saved synchronously to `userData/home-recovery-gave-up.json`, then restored to the caregiver's reliability log and deleted on the next start.
- **Volume:** the volume ceiling uses the `loudness` native module, with a C# fallback (`resources/reliability/VolumeHelper.cs`; the compiled DLL is gitignored).
- **Wi-Fi:** `wifiHealer.ts` handles adapter discovery and self-healing.

### Caregiver checks

- **Panel:** admin's Checks tab (`components/ChecksTab.tsx`) runs four checks, one at a time, on her actual computer: Buddy's voice, the microphone, the internet connection, and getting back Home from a broken page. The logic is `services/checks/caregiverChecks.ts` (every dependency injected, unit tested) behind `ipc/checksIpc.ts`. Every `checks:*` handler calls `requireAdminUnlocked()`, and `onAdminLocked()` in `adminAuth.ts` cancels whatever is running, as do Stop, leaving the tab and the admin window closing or reloading. Results are kept in memory only and carry `checkedAt`; the panel always shows the time and calls a result older than 10 minutes history, so neither a restart nor an old pass reads as "working now". Results log as content-free `caregiver-check-<id>-<status>` activity events.
- **Voice:** main synthesizes the test line with the saved Edge voice, or tells the panel to use the Windows voice and says whether that is the setting or a fallback. The panel plays it under a `buddyVoice` audio hold and reports `played`; only then, and only for that run, can the caregiver answer heard or not heard. Playback finishing is never a pass. `lastHeardSound()` is the record TASK-25's dashboard should reuse rather than keep its own.
- **Microphone:** one `listenOnce` under a main-owned `listening` audio hold. `runPowerShell` takes an `AbortSignal`, so cancelling kills the recognizer. What it heard goes back to the panel once and is never stored or logged.
- **Connectivity:** Windows' online state (through the same e2e stand-in as the recovery screen), then Windows' own probe address (`msftconnecttest.com/connecttest.txt`); any other reply is reported as a sign-in page in the way.
- **Browser recovery:** refused while a page is open, so it never closes hers. Main reserves a closed local port and sends `checks:recovery-start`; Home opens it, only from plain Home, through the launcher-only `browser:openRecoveryCheck`, which carries no address. Once the recovery screen's state appears, main closes the page with `closeEmbeddedBrowser()` (her Home button's path) and sends `browser:return-home`. Cancelled or failed runs close the check page too.

### Buddy chat

- **Main process only:** `buddy:chat` → `services/ai/buddyChatService.ts`. ChatGPT is the only chat provider. The session (`services/chatgpt/`), Responses adapter and frozen system prompt (`buddyPrompt.ts`) live in main. Schema 020 removes legacy provider keys and models. A completed model test is required before chat is available. See `docs/buddy-chatgpt.md`.
- **Fixed actions:** `shared/buddy/actions.ts` permits playMusic/showPhotos/goHome and opening a visible saved Home tile by its current name. Whole explicit typed/spoken requests ("open …", "go to …", "show me …") resolve in main before the API/key check; one that names no saved tile at all ("show me how to make tea") goes on to chat when chat has a key, and gets the calm unavailable reply when it has none. General wording can propose the fixed `open_saved_tile` tool with only a name. Names compare case-insensitively, ignoring a leading the/my/a. Main validates every request against current config using Home placement rules (overflow and hidden tiles are excluded), and duplicate names produce large choices in chat with their Home positions, without moving tiles. Choices recheck the saved ID and expected label; plans carry only the saved tile ID. The renderer rechecks its live config and opens through the same App path as a tap. Buddy opens saved web tiles through ID-only `browser:openTile`, which waits for the page: loaded confirms, a failed load keeps Home's recovery screen (as after a tap) and says it didn't open, and a page still loading after 20s gets no claim either way. Taps keep `browser:open` and the "Opening …" toast; native apps wait for launch, built-ins open their registered view, and failures never claim success. Existing music confirmation still waits for real playback. `buddy:action`, chat proposals and listening are launcher-only and respect the chat switch. Talk remains deliberate; closing chat cancels the recognizer through its injected runner. The frozen prompt is unchanged; tools carry their own descriptions and accompanying model text is discarded. Requests, requested tile labels, song titles and photo captions are never logged.
- **History:** the renderer keeps the on-screen history and sends it every turn; the service sanitizes it (`toApiMessages`).
- **Replies:** every result carries a `reply` that is safe to show her, including on failure. Technical detail goes to the activity log, and chat content is never logged. The activity log (`services/activityLog/activityLog.ts`) keeps only the last 1000 events in memory and is not saved to disk.
- **Off switch:** `buddy.chatEnabled` (admin Buddy tab) is enforced in main: when it is off, `buddyChat()` returns the gentle `disabled` reply without creating a client or calling the API. Home closes an open chat, drops the Let's chat invitation and menu row, and treats a `chat` tap action as a reaction. Buddy, his tap reactions and caregiver commands stay.
- **Model:** choices come from the connected ChatGPT account. A completed reply test verifies the selected model before Buddy can use it. Finished stream items remain provisional until `response.completed`; terminal responses may omit their output list. The four live synthetic checks are recorded in `docs/buddy-chatgpt.md`; they do not establish suitability with the kiosk user.

### Buddy on Home

- **Behavior:** `src/shared/buddy/buddyMachine.ts` is an xstate machine (greeting, resting, fidgeting, strolling, remarking, chat.*, farewell), pure and tested with a `SimulatedClock`. Positions are fractions of his floor (0..1), never pixels. `buddy.motion` selects `still` (usual gestures, no unprompted strolls), `roam` (the original behavior), or `reduced` (no unprompted strolls or fidgets). Reduced motion uses `idle_calm`, `wave`, `listen`, `talk` and `heart`: remarks stay on the calm idle, thinking uses listening, and each spoken reply gets one talking gesture before settling. He stays at his live position even when chat opens. Settings arrive through `config:changed` and update the running actor; switching off roam stops an unprompted stroll at its live position, and switching to reduced stops a fidget immediately. Deliberate walks are preserved. Night (9 PM-6 AM) means no unprompted strolls or remarks. Every one-shot state has a 20s `clipTimeout` so a missing clip can't freeze him. Remark lines live in `remarks.ts`: never a question she must answer, never a claim that might be false.
- **Rendering:** `renderer/launcher/src/buddy/BuddyFloor.tsx` spans the Stage's full width above its bottom padding; the footer reserves 150px. Its orthographic canvas takes no pointer events; the invisible tap button and bubble follow him per frame. `useBuddyBrain.ts` runs the actor (created in an effect because of StrictMode). `CatModel.tsx` crossfades clips and slides him at the walk clip's stride speed. With `buddy.tapAction: 'chat'`, tapping opens chat directly with no reaction or invitation. The default `reaction` tap sends a friendly line and matching happy gesture from the pure `shared/buddy/tapReactions.ts` pool, avoiding the previous tap's line and clip (reduced motion keeps only wave and heart reactions); `buddy.voiceEnabled` controls tap read-aloud through the existing speech path. Rapid pats restart the command; both tap actions are excluded from confusion detection; tapping during chat stays a pet. A reaction tap also shows a large 💬 Let's chat button in the moving bubble for eight seconds, independent of the gesture ending; another tap restarts it, then it fades. It works at night, and opens the chat panel without another reaction or confusion-detection tap. Opening chat, the caregiver menu or leaving Home dismisses it immediately. `Ctrl+Shift+B` opens a compact translucent `BuddyMenu` above his live tap target, captured in scaled Stage coordinates and clamped inside the Stage. The shortcut, Esc or an outside click closes it; arrow keys and Tab cycle rows and focus returns on close. It is available only on unobscured Home.
- **Commands:** `shared/buddy/commands.ts` owns the 29 clip names and command validation. Admin invokes `buddy:command`, gated by `requireAdminUnlocked()`, and main pushes the validated command to Home. The machine's `commanded` state carries a forced clip and sequence (so repeated clips restart), ends on `CLIP_DONE` or the 20s timeout, and is ignored while chatting. Deliberate commands work at night. The shared `walk` command (also in admin) enters `strolling` directly, choosing a destination at least a third of the floor from his live rendered position in every motion mode, then rests on `ARRIVED`. Walks are ignored during chat and cancel earlier command speech. Optional read-aloud may outlast the gesture, but stops on another command, chat, or leaving Home. Saved messages live in `buddy.quickMessages`; never log their content.
- **Chat panel:** rendered inside the Stage (not over the window) so his floor can sit above its backdrop at `zLayers.buddyInChat`. It reports a `ChatPhase` (idle/hearing/thinking/speaking) that drives his chat states.
- **Voice:** `buddy:speak` → `services/speech/ttsService.ts` (Edge neural voices via `msedge-tts`, XML-escaped, 10s timeout). On any `ok:false` the renderer (`buddy/speech.ts`) falls back to `speechSynthesis`. Chat lines, tap reactions (when read-aloud is enabled) and explicitly requested caregiver messages can be spoken; unprompted remarks are bubble-only.
- **Listening:** `buddy:listen` → `services/speech/sttService.ts`, Windows' offline System.Speech dictation through `runPowerShell`, one phrase per call. `buddy:canListen` gates the Talk button. Log that she spoke, never what she said.
- **CSP:** the launcher allows `blob:` for img/media/connect (GLB textures, voice audio). `useGLTF` must be called with Draco and Meshopt off: one fetches from a CDN, the other compiles WebAssembly, which `script-src 'self'` blocks.
- **Canvas sizing:** `<Canvas>` takes `resize={{ offsetSize: true }}` in `BuddyFloor.tsx`. The Stage scales a fixed 1440x900 design with a CSS transform, and R3F measures with `getBoundingClientRect`, which already includes that scale — so the canvas would be sized in scaled pixels and scaled again. Measuring layout (offset) size keeps his zoom, walking range and tap-target projection identical at every screen size; a transform change also fires no `ResizeObserver`, so without it the wrong size never recovers on resize.

### Buddy's model

`scripts/blender/fixCatRig.py` (run by `buildBuddy.sh`) turns Meshy's humanoid auto-rig into something that fits a round cat: it lowers the hip/knee joints along their original bone directions (so clip rotations still mean the same thing), re-weights legs and belly with bone heat against a joint-to-joint copy of the skeleton, pushes hanging arms out of the belly, re-grounds each clip to Meshy's own foot-height profile, makes the material matte, and exports every clip into one GLB. Clips come from Meshy's animation library (`meshy animate create --rig-task-id <rig> --action-id N -o CatModel/meshy/<dir>/<name>`); clip names in `buildBuddy.sh` must match `BUDDY_CLIPS`. The first 24 clips (`anims/`) came from rig task 01a0dcaf-4f10-746b-86fa-75e22623504f, which has expired on Meshy's side. Its skeleton stays the one Buddy ships with. Later clips (`anims2/`: doze, hooray, big_stretch, funny_dance, groove) come from a re-rig of the same `remesh/model.glb` at 1.35 m (rig task 01a17bbc-4c5f-70cc-bc5d-6280f0f69690, which will expire too). That rig puts the joints and bone orientations elsewhere (hips 11 cm lower), so `fixCatRig.py` detects a clip from another rig and retargets it: per frame, each bone gets its source world-space rotation change from rest, hips movement is scaled by hip height, and the source rig's foot heights become the clip's re-ground profile. The original clips come out byte-identical. When this rig expires too, re-rig again and add the clips the same way. Never mix clips into `anims/`. Check new clips by rendering frames from the built GLB in Blender: a clip that ends facing away (Meshy's Indoor Swing) snaps when it crossfades back to idle.

### Built-in tiles and News

- **Registry:** each built-in tile kind is one entry in `renderer/launcher/src/tiles/builtins.tsx` (its well icon and the view it opens), keyed by `BUILTIN_TILE_KEYS` in `configSchema.ts`. `App.tsx` holds whichever built-in view is open (`openBuiltin`), so a new kind adds an entry there, not another branch in App.
- **News:** a `builtin` tile with `builtinKey: 'news'`, its feed in `feedUrl` and optional site in `url`. `feedUrl` is optional in the schema, so version-4 configs stay valid without a migration. Fetching is main-only (`services/news/newsService.ts`): 10s timeout, 2 MB cap, 15-minute cache per tile, and the last good stories (marked stale) if a refresh fails. Feeds are decoded in their declared charset (BOM, then HTTP `charset`, then the XML declaration, then UTF-8). Thumbnails are fetched in main (raster types only, 300 KB cap) and sent as `data:` URLs, so the launcher CSP doesn't loosen. The feed publisher chooses thumbnail URLs, so every DNS result and every redirect hop (at most 3, followed manually) must be a public address (`publicAddress.ts`); the caregiver-chosen feed itself isn't restricted. Known gap: fetch resolves the name again, so DNS rebinding isn't pinned. `shared/news/parseFeed.ts` is a dependency-free RSS/Atom reader that outputs plain text only and fails closed on DTDs or broken markup. Never render feed content as HTML.
- **IPC:** `news:get` and `news:open` take a tile id (and story id), never a URL: main fetches only the saved feed and opens only the saved site or a story it served. Story browsing is opened with `privateNavigation`, so the logs record `news-story-opened` but not the article address.

### Media protocol

`grammie-media://<library>/<fileName>` serves image and audio files from `userData/media/music/`, `userData/media/photos/` and `userData/media/narration/` only (folder constants in `services/media/libraryPaths.ts` for import services). News thumbnails remain `data:` URLs. The scheme is registered before ready and its streaming handler before windows load; single byte ranges support audio seeking. Missing files or folders and invalid requests return a path-free 404; invalid or unsatisfiable ranges return 416.

Pure validation in `shared/media/mediaPath.ts` decodes filenames once and allows 1–255 ASCII letters, digits, dots, underscores and hyphens, with no `..`, trailing dot, or Windows device names (including extensions). Slashes, backslashes, spaces, malformed/double encoding, query strings and fragments are rejected. The handler also checks resolved paths for library escapes, including symlinks. Renderers get no filesystem API for these libraries; the protocol enforces access regardless of sandbox settings. Both launcher and admin CSPs allow the scheme for images and media only, without `bypassCSP`.

**Library store:** `services/media/libraryStore.ts` has one instance per library, created in `ipc/libraryIpc.ts`. Its `index.json` lives in the library folder, not in config, because the lists can hold hundreds of entries. Imports copy each file to `<uuid>.<ext>` through a flushed temp file and publish the index last, so an interrupted import leaves no half entry; source paths are never stored or returned. Mutations are queued per library. A missing index starts empty. A corrupt one is renamed to `index.json.corrupt-*` and the library starts empty; if that backup fails, writes are refused rather than overwrite it. A briefly unreadable index (EBUSY, EPERM) fails only that request and is read again next time. The admin `library:list/import/update/remove` channels call `requireAdminUnlocked()` first, import goes through the native file picker only, and filesystem errors are replaced with path-free messages before they cross IPC.

**Photo library:** Photo mutations use `photos:import/update/remove`; generic `library` mutations are now music-only so they cannot bypass the photo pipeline. `services/photos/photoLibrary.ts` uses an injectable codec and `LibraryStore.addImage()` to publish `<uuid>.jpg` and `<uuid>.thumb.jpg` before the entry. Captions, `showToHer` and order are metadata in the library index. Both images are resized by their longer edge (at most 1600 and 320) and encoded with `nativeImage.toJPEG(85)`. Direct nativeImage decoding is PNG/JPEG-only; `nativePhotoCodec.ts` falls back to nativeImage's Windows Shell thumbnail decoder for WebP/HEIC, with unavailable codecs counted as per-file failures. Imports yield between files and push count-only `photos:importProgress` to the requesting admin. `photos:listAll/import/update/remove` call `requireAdminUnlocked()` first; `photos:listVisible` is exposed to the launcher and returns only approved photos in caregiver order. Photo responses contain only `grammie-media://` image URLs and metadata. Older raw entries remain hidden until a caregiver approves them. Games are a separate task. The Photos built-in view (`tiles/PhotoViewer.tsx`) opens through `photos:open`: visible photos only, with a content-free `photos-viewer-opened` activity event. Large Home/Back/Next buttons and keyboard focus stay usable in empty/error states. Caregiver-enabled slideshow waits 30 seconds from each loaded picture, supports Pause/Play, resets on manual paging, stops on image failure, and clears its timeout on unmount. Long captions scroll separately from the picture and controls.

**Photo stories:** a recorded or attached story lives in its own `narration` library (`services/photos/photoNarration.ts`), keyed by `photoId` in the entry metadata; the newest entry for a photo wins and replacing one removes the old copies. `photos:*` responses carry it as `narration: { url, autoPlay }`. `ipc/narrationIpc.ts` accepts story changes only from the unlocked admin window; recordings arrive as bytes (always WebM) and attached files only through the native picker, both capped at 20 MB and checked with music-metadata (five minutes when a duration is known). Photo and story changes share one queue (`runPhotoOperation`) so a removed photo can't keep its story; reads and pickers stay out of it, so Home's viewer never waits on an open picker or a long import. `services/photos/adminMicrophone.ts` installs the default session's permission handlers: they grant only audio capture, only to the unlocked admin document, and deny every other permission to Home and admin (web tiles keep their own session's handlers). Stories are not part of settings backups. Home and admin play them through `renderer/audio/useNarration.ts` under a `narration` audio hold; the viewer pauses the slideshow while one plays and stops it on paging or leaving.

### Embedded browser

Web tiles open in a `WebContentsView` (not the deprecated `BrowserView`) overlaid below a 72px nav bar (`services/browser/embeddedBrowser.ts`). `urlPolicy.ts` holds the protocol allow-list. Navigation guards and popup blocking stop the user from escaping the kiosk. `shared/browser/approvedSites.ts` restricts main-document opens, links, redirects, retries and Back navigation using the current saved web tiles (also the News fallback website) and `approvedSites`. Child frames, images and scripts are not filtered by this policy. `siteFor()` turns a host into the site to approve: it drops only a leading `www.` (`www.bbc.co.uk` approves `bbc.co.uk` and its subdomains, never `co.uk`), or keeps the exact host when dropping it would leave only a shared ending (`www.gov.uk`). Shared endings come from a hand-kept list in `SHARED_SUFFIXES` (common country second levels such as co.uk and com.au, plus hosting platforms such as github.io); it is not the full Public Suffix List, so an unlisted ending typed by hand could be approved as a whole. An earlier guessing rule (two-letter country code after a short name) refused real sites such as cbc.ca and blocked their tiles. IPs and localhost match exactly, on any port. Admin's Sites tab saves additions/removals through `config:set`; every navigation reads current config, so approvals take effect live. `browser:blockedSites` requires admin unlock and exposes only the last 50 distinct blocked domains, held in memory. Block logs contain a domain only; private News browsing omits even the domain from activity/reliability logs. `news:open` gives only its exact main-served story a page exception (also used for retry/Back); links and redirects never inherit it. Private logging alone grants no exception. The caregiver recovery check also grants its main-chosen closed-loopback page an exact-page exception so its failure can still be tested. The browser closes after `confusion.inactivityTimeoutMinutes` of idle time; taps, keys, scrolling and touches inside the page count as activity through the `browserView` preload.

### Audio rules

`src/shared/audio/audioPolicy.ts` is the one rule for overlapping sound (music, photo narration, Buddy's voice, Buddy listening, web page sound). `services/audio/audioCoordinator.ts` applies the rule, schedules its delayed decisions and broadcasts revisioned `audio:changed` updates. `audioRuntime.ts` owns renderer holds and clears them on main-document replacement, crash or destruction. `audio:event` validates events and limits clients to Home and unlocked admin; owned cleanup remains allowed after locking. `renderer/audio/audioBridge.ts` shares leases across Buddy speech/listening/chat and admin previews. `pageAudio.ts` turns embedded-page audibility into holds and applies muting, with cleanup on close. Photo stories use the same lease path (`useNarration.ts`), and admin recording holds `listening`. Listening, narration, an open chat and an audible web page pause music; Buddy's voice outside chat lowers it. Music comes back `RESUME_DELAY_MS` after the hold ends, so turns don't make it stop and start. One voice plays at a time (newest wins), no voice plays while he listens, and page sound is muted while a voice plays or he listens. Stop works in every state, and while music is on a Stop must show on every screen, including the browser's nav bar.

When the page fails to load, or a link is blocked, the native view is hidden (it would cover anything Home draws) and `browser:page-problem` tells Home to show `PageRecovery`: plain words, large Try again/Back to the page and Home buttons, never an error code, with the nav bar left in place. `shared/browser/loadFailure.ts` (pure) sorts a main-frame failure into 'offline' (connection errors, or Windows reports offline) or 'unreachable', ignores ERR_ABORTED, and builds the caregiver's log line: domain plus Chromium's error name, never the full address. The page is shown again only when a retry finishes loading. A blocked redirect from a fresh tile open keeps the recovery screen visible even after ERR_ABORTED; if no page ever committed, Back to the page closes the view and returns Home instead of showing a blank view. While offline, main retries every 5s once Windows reports a connection; those retries don't count as her activity, so the idle timeout still closes an unattended page. Chromium's offline emulation stalls loads instead of failing them, so e2e stands in for Windows' online state with `__e2e__.setDeviceOnline()`.

### UI conventions

- **Stacking order:** every z-index comes from `src/shared/zLayers.ts`. Never hardcode z-index values.
- **Tile positions:** Home is a fixed layout from `shared/homeLayout.ts` (`simple4` 2x2 or `more8` 4x2, never scrolling). Each tile's saved `slot` is permanent: helpers never compact holes, a wide tile takes two adjacent slots in one row, and `slot: null` is overflow that stays in config but isn't shown. `config:set` keeps valid slots, gives slotless new tiles the first hole, and re-places tiles in slot order on a layout-only change. Migration 008 picks the layout and places existing tiles in their old order.
- **Tile colors:** a tile's color is its saved `colorIndex` (a palette slot 0-3, `shared/tileColors.ts`), never its position, so reordering can't repaint Home. `config:set` keeps a tile's saved color when a patch omits it and gives new tiles the least-used slot.
- **Card artwork:** `shared/tileArtwork.ts` decides a tile's picture: a chosen photo wins, then a saved icon, then the caregiver's named `artwork`, then the default for Photos/Music/Weather/News built-ins. It is never guessed from a label or URL and never changes what the tile opens. `BuiltinArtwork.tsx` crops two bundled transparent atlases in `renderer/launcher/src/assets/home-cards/`: quadrants for the four built-ins, and measured alpha-bounds frames for Games and Websites, so a regenerated atlas needs those frames measured again. If an atlas fails to load, the built-in SVG icon shows instead. Normal-width More choices cards stay label-only unless they have a photo.
- **Themes and fonts:** these live in `src/shared/theme.ts`. Font size is a discrete step index (`FONT_STEPS`), not a raw scale. Only the caregiver changes it, in admin's Display tab; Home deliberately has no text-size buttons, so a stray tap can't change it. The `clayCards` theme (cream ground, larger card labels) is opt-in so an update never repaints her Home. A token that only some themes set (its `card-*` and `category-card-*` sizes) must be listed in `THEME_ONLY_KEYS` in `shared/theme.ts`; Home and admin's Home preview clear them on a theme switch so they don't stick to the next theme.
- **Admin Home preview:** `admin/src/components/HomePreview.tsx` renders Home's own `HomeHeader` and `TileGrid` (Buddy's Three.js floor stays out of admin) as a scaled, non-interactive preview (fixed 1440x900 design size scaled via CSS transform, marked `inert` and `aria-hidden`) in both Tiles and Display tabs; her theme tokens and `--font-scale` are applied to the preview container alone, clearing `THEME_ONLY_KEYS` on theme change so admin's root styling is untouched.
- **Visual style:** the "clay" look (`renderer/launcher/src/clay.ts`) is ported from the design files in `UI Screenshots/clay-launcher-design/`, especially `GrammieGuide Home.dc.html`. Treat those files as the visual reference. The illustrated Home cards extend it: root `DESIGN.md` records their tokens, and `design/home-cards/implementation.md` records the approved concepts, measurements and review limits.
- **Confusion detection:** the rapid-tap detector is pure logic in `src/shared/confusionDetector.ts`, which is unit tested.
- **Idle dimming:** opt-in from admin's Display tab (`display.idleDim`). The timing rule is pure in `shared/idleDim.ts`; `components/useIdleDim.ts` feeds it. A window capture-phase listener treats the first tap, key or scroll while dimmed as a wake-up: it brightens at once and swallows that event (and the click or keyup that follows), so it can't open a tile, start a chat or count toward confusion detection. Buttons marked `data-music-stop` pass through, so Stop works on the first touch. Home never dims while a web page is open (its native view can't be veiled, and it has its own idle close), while chat is open, or while the audio coordinator reports a hold (`AudioDecision.hasHold`: Buddy speaking or listening, narration, chat, page sound); time spent in any of those restarts the idle time. Music alone is no hold. The veil (`IdleDimOverlay`, `zLayers.idleDim`) sits over everything with `pointer-events: none`, fades in over 1.5s (instantly with reduced motion) and clears instantly. State is in memory, so a restart or Home recovery starts bright. TASK-22's help request should pass its pending state as the `contactFlow` blocker.

### Music library

Admin Music imports MP3, M4A, AAC, FLAC, OGG and WAV through the native picker. Main-only music-metadata reads tags, duration and optional cover art; nativeImage converts art to a bounded JPEG thumbnail. LibraryStore.addFile publishes the audio, optional cover and metadata together under generated names, preserving sources and rolling back failed writes. Music IPC and legacy library removal share the same library store; removal saves reference cleanup before deleting files, preventing deleted tracks from remaining in playlists. music:list/importFiles/saveSettings/removeTrack are admin-only, with lock rechecks after queued work and the picker. Config holds up to six named, ordered playlists with shuffle. Music settings validate track references against the saved library. No song title, artist or source path is logged. `launcher/src/music/musicPlayer.ts` owns one persistent HTMLAudioElement, a bounded queue, shuffled cycles, missing-file skips and the auto-stop deadline. It follows coordinator decisions rather than choosing overlaps itself. Pending play attempts are invalidated by pause/hold so intentional interruption cannot mark a valid song unavailable. The Music overlay, Home chip and browser nav expose Stop; other built-ins and chat keep it visible. `music:getPlaylists` is launcher-only and returns only configured tracks; `music:report` logs allowed events by saved playlist ID.
